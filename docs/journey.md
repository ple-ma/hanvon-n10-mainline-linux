# N10 移植过程记录

这不是教程，是一份破案笔记。想直接动手的看 README 和各目录的说明就行；这里记的是每个问题
怎么找到的，包括走错的路。设备是汉王 N10：RK3566，10.3 寸墨水屏（ED103TC2U2），带一根电磁笔。
目标很朴素：让它跑主线 Linux，屏幕能看，笔能写，日常能用。

## 一、先跑起来再说

N10 的 Android boot 分区没什么神秘的：标准 Android boot 镜像格式，里面是内核加 initramfs。
真正麻烦的是怎么把镜像送进去。Rockchip 平台有两条路：loader 模式（短接测试点或用工具触发）
和 BCB（往 bootloader_message 分区写 boot-recovery）。两条都试了，都通。BCB 的好处是不需要
拆机，写完重启就进 loader；loader 的好处是救砖时它总在。

第一次点亮用的是 PineNote 的 6.6.30 内核树。选它没有别的原因：那棵树上有 rockchip ebc 墨水屏
驱动的雏形，别人替我们把最难啃的骨头啃了一半。设备树自己写，屏幕、笔、按键、电源，一项项加。

## 二、屏幕左右是错乱的

屏幕亮了，但不对：画面左右两边出现错位的条纹，像是相邻行的数据互相串了。这个问题花了最
长时间，因为它没有明显的原因。

先猜行跨度（line stride）不对，量了一下，对的。再猜面板时序，对照数据手册逐项核，没发现
异常。最后把方向换到面板的消隐区：rockchip ebc 的扫描会把帧缓冲最上和最下的一小段扫到
相邻行上，而 panel-simple 里的 vtotal 补偿恰好能控制这段多余扫描线落在哪里。在 panel-simple
里加上补偿，条纹消失了。补偿值先按经验给了 20，后来实测调到 5，两边都干净。

这段的教训：墨水屏的时序问题未必是"时序错了"，也可能是"时序对了但扫描窗口和帧缓冲没对齐"。

## 三、电磁笔

原厂系统里笔是好用的，但驱动是闭源模块，指望不上。自己来。

先搞清楚数据从哪来。电磁笔的数字化仪走的是 uart5，TTL 电平，57600 波特率。接上逻辑分析仪
般的笨办法：写个采样程序把串口数据全 dump 下来，拿着笔在屏幕上画，对着原始字节找规律。
很快就有发现：数据是 7 字节定长包，连续出流，帧头字节最高位是 1 且低 4 位不超过 5。

坐标编码也拆出来了：

```
x = (b1 << 9) | (b2 << 2) | ((b6 >> 5) & 3)
y = (b3 << 9) | (b4 << 2) | ((b6 >> 3) & 3)
```

11 位坐标，拆在 4 个字节里，尾部字节还捎带了两个轴的低 2 位。压感和笔按键在另外的字节里，
配合帧头的低位区分。

有了协议，剩下的就是工程：一个守护进程读串口、解析、通过 uinput 注册成标准指针设备，取名
hanvon_pen。坐标用四角校准做线性映射，写进 /etc/pen-calib。这套东西没有任何逆向出来的代码，
只有协议事实和我们自己的实现。

顺带发现原厂内核里那个闭源笔驱动的 sysfs 节点只能改一个内存变量，改了没什么效果。这条路
一开始就该放弃，不过确认它没用本身也是有用的信息。

## 四、唤醒之后是白屏

休眠本身没难度，标准流程。唤醒才是问题：每次唤醒后整块屏幕泛白，像蒙了一层雾，刷新也刷
不掉。

顺着电源链路查。墨水屏的电源由一颗 fp9931（e-paper PMIC）管理，负责 vcom、正负压和上电时序。
休眠唤醒之后白屏，十有八九是 PMIC 的状态没被正确恢复。原来的内核里 fp9931 驱动是缺失的，
电源部分全靠默认值硬扛。

从上游把 fp9931 驱动搬回来（Andreas Kemnade 写的，GPL，直接用）。装上之后唤醒白屏消失。
回头看这属于"该有的驱动没有"引发的问题，跟屏幕本身没关系。

## 五、GUI

GUI 的设计原则是绕开所有显示服务器。X11 在墨水屏上又慢又没必要，直接读写 /dev/fb0 就好。

先搞清楚帧缓冲的方向：fb0 的缓冲是 1872×1404 的横屏布局，而设备是竖着用的。所以画图时在
1404×1872 的画布上画，写进帧缓冲前旋转一次，输入坐标再做一次反向映射。第一版屏幕全黑就是
因为忘了这层变换。

终端用 pyte 在内存里维护一个终端仿真，从 /dev/vcsa1 拿内容渲染。屏幕键盘的按键通过 uinput
直接注入到 tty，效果和敲实体键盘一样。WiFi 用 wpa_cli 扫描连接，弹窗里配密码。

墨水屏的刷新和普通屏幕不一样，全刷会闪一下黑。策略是这样的：打字的时候不刷新，让终端自己
的回显更新；只有开关键盘、开关 WiFi 弹窗这类大变化才全刷一次；弹窗里的小动作用局部刷新。
另外内核里的刷新模式（mode）对体感影响很大，mode 2 明显比 mode 4 流畅，选 2。

## 六、按键、电池、温度

9 个实体按键走 gpio-keys，注册成标准输入设备后在 GUI 里绑功能：翻页、音量、刷新、休眠。

电池电量从 rk817 的 fuel-gauge 拿，充放电状态、百分比，画到状态栏。这些是整个项目里最顺利
的部分，标准子系统，接上就好。

墨水屏的波形对温度敏感，驱动里有温度补偿的入口（temp_override），但 N10 上没有可用的
温度通道，驱动直接忽略了这个参数。改成没有温度通道时也认这个参数，手动指定补偿值。

## 七、声音

喇叭接在 rk817 codec 上。驱动都在，但声卡死活不出来。查到最后是设备树绑定的问题：
rk8xx-core 注册 codec 子设备时没把设备树节点挂上去，驱动探测时找不到自己的配置，直接不绑。
补一行 of_node，声卡出来了，喇叭响了。

这种 bug 不看代码根本想不到，声卡不出现的报错信息里没有任何线索。

## 八、USB

最后是 USB。RK3566 的 DWC3 控制器配成双角色，TypeC 口可以当主机。插 hub，hub 上挂键盘、
U 盘，都能识别。键盘接上后 GUI 里特意做了个处理：屏幕键盘弹出时终端窗口上移，不挡住键盘区。

USB 千兆网卡（AX88179A）卡在驱动上：6.6 内核里的驱动版本太老，识别不了，需要从新内核
backport。编到 probe 阶段时这一项就搁置了，不影响其他功能。

到这里，这台电子书就变成了一台能插键盘、能联网、能放歌的 Linux 小机器。
